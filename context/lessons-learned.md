# Lessons Learned

- **Refatoração Arquitetural SRP (Decomposição de God Classes):** Durante a auditoria do Gunter, identificou-se que `LoginPage`, `InventoryPage` e `CheckoutPage` acumulavam múltiplas responsabilidades (Menu Lateral, Detalhes de Produto, Rodapé e as 3 etapas distintas do Checkout). A extração de `HeaderComponent`, `SideMenuComponent`, `FooterComponent` e `ErrorBannerComponent` em `pages/components/` e a divisão em 7 Page Objects (`LoginPage`, `InventoryPage`, `ProductDetailPage`, `CartPage`, `CheckoutInformationPage`, `CheckoutOverviewPage`, `CheckoutCompletePage`) reduziram todos os métodos para menos de 15 linhas e eliminaram código duplicado.
- **Padronização Total de Fixtures em `tests/login.spec.ts`:** O arquivo inicial `login.spec.ts` ainda instanciava `new LoginPage(page)` manualmente. Foi migrado para `fixtures/pom.fixture.ts` com `test.beforeEach` e constantes de `test-data/app-content.ts`, unificando 100% da suíte no mesmo padrão arquitetural.
- **Correção de Pipeline CI/CD (`Missing X server or $DISPLAY` no Ubuntu Runner):** Em servidores Linux de CI (GitHub Actions `ubuntu-latest`), não há servidor gráfico X11 (`$DISPLAY`). Configurar `headless: false` e `channel: 'chrome'` de forma fixa causa falha na inicialização do browser no pipeline. Solução definitiva em `playwright.config.ts`: parametrizar via `const isCI = !!process.env.CI`, mantendo `headless: false`, `slowMo: 600` e `channel: 'chrome'` no ambiente local e aplicando `headless: true`, `slowMo: 0` e Chromium nativo no ambiente de CI.
- **SLA de Auto-Wait para `performance_glitch_user` (10s):** O perfil `performance_glitch_user` injeta um bloqueio intencional de 5000ms na transição de login. Com `slowMo: 600` ativo para visualização, `actionTimeout: 10000` e `expect.timeout: 10000` permitem absorver essa latência nativamente via *Auto-Wait*, sem qualquer `waitForTimeout` estático.
- **Self-Healing de Links Sociais no Rodapé (ARIA Role vs `data-test`):** O Swag Labs atualizou o antigo link do Twitter para `X` (`https://x.com/saucelabs`) na árvore de acessibilidade (`getByRole('link', { name: 'X' })`, `Facebook`, `LinkedIn`). O uso de `getByRole('link', ...)` validado pelo snapshot do Healer garantiu resiliência sem depender de classes CSS.
- **Execução Enxuta em CI:** Instalação restrita ao binário Chromium (`npx playwright install --with-deps chromium`) reduz drasticamente o tempo de provisionamento no GitHub Actions.
